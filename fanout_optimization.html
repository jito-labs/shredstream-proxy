Shredstream Fanout Optimization — All-Runs Comparison

Each chart plots one metric from shredstream_proxy-forwarding_perf datapoints (emitted every ~10s by proxy/src/forwarder.rs). Each line is one test run; the x-axis is the in-run sample index (1..N) since runs span different wall-clock times.

How to read these numbers — two layers of aggregation.
  • Per-batch: one batch = one call to recv_from_channel_and_send_multiple_dest (one packet → ~20 dest sendmmsg fanout).
  • Per window (≈10s, ~24k batches): the proxy emits one log line every ~10s aggregating those batches into avg_* (mean across batches) and max_* (worst single batch in the window).
  • Per run (this dashboard): the summary table then aggregates the ~44 window samples in a run into avg / p50 / p99. So a header like avg max_total_us means "average, across windows, of each window's worst-batch total_us" — i.e. typical tail. p99 max_total_us ≈ the worst window in the run.
Source line: datapoint: shredstream_proxy-forwarding_perf batches=Bi packets=Pi dest_sends=Di avg_total_us=Ui avg_dedup_us=Di avg_fanout_send_us=Fi avg_max_per_dest_us=Mi max_total_us=Ti max_fanout_send_us=Si max_per_dest_us=Pi
